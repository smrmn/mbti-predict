# MBTI Predict Bot

Telegram-бот `@noo_sphere_bot`. Две независимые части в одном процессе:

1. **MBTI-предсказания** — тест из 16 вопросов, тип в профиль, каждый день
   в 09:00 МСК предсказание через OpenRouter (бесплатные модели по очереди,
   `services/prediction.py`). Подробно — README, «Механика».
2. **Слежение за обменом ETH ↔ WBTC** — личный инструмент владельца, ниже.

**Репозиторий публичный.** Никаких сумм, позиций, истории обменов, chat_id
и username владельца в коде, README и коммитах — только на сервере
(`/etc/mbti-predict.env`, `/var/lib/mbti-predict/swap_watch.json`).

## Код

## Слежение ETH ↔ WBTC

### Позиция и выгода

Позиция — что на руках (`asset`, `amount`) и сколько другой валюты за это
отдали (`base`). Выгода — на сколько процентов больше другой валюты выйдет
при обмене сейчас, чем отдали:

```
ETH на руках:  out = amount × курс ETH/WBTC
WBTC на руках: out = amount ÷ курс ETH/WBTC
выгода = (out / base − 1) × 100
```

Считается **на кошелёк**, по сумме, которая реально придёт при обмене через
MetaMask Swaps (владелец меняет там, сеть Ethereum):

```
dex  = котировка KyberSwap на всю позицию (с проскальзыванием на этой сумме)
газ  = gasUsd из той же котировки, в получаемой валюте
net  = dex × (1 − SWAP_FEE_PCT/100) − газ      ← выгода считается по нему
```

- KyberSwap — публичный агрегатор без ключа (`/ethereum/api/v1/routes`,
  заголовок `x-client-id`); рыночный курс берётся из его же USD-цен.
- Не ответил — фолбэк на CoinGecko: рынок минус комиссия, без газа; в `/swap`
  это видно.
- `SWAP_FEE_PCT` = 0.875 — сервисная комиссия MetaMask Swaps. Она и есть почти
  весь отрыв обменов владельца от рынка: проскальзывание на его объёме ~0.05%,
  газ ~0.03% (сверено по истории). Меняет напрямую через агрегатор — ставить 0.
- В `/swap` и в уведомлении главное — строка с 💰: сколько придёт
  на кошелёк и выгода, жирным. Рынок, DEX, комиссию и газ не показываем —
  владелец попросил без второстепенного.

### Фазы — trailing stop с полом

| Фаза | Что происходит | Переход |
|---|---|---|
| `idle` | ждём порог, курс раз в `SWAP_CHECK_MINUTES` (5) мин | выгода ≥ `SWAP_GAIN_PCT` (2%) → `armed`, пик = выгода, **молча** |
| `armed` | курс раз в минуту, пик = max(пик, выгода) | откат от пика ≥ `SWAP_TRAIL_PCT` (1 п.п.) → сообщение «откат от пика», `fired`; выгода < порога → сообщение «вернулся к порогу», `fired` |
| `fired` | молчим | выгода < порога → `idle` (взводимся заново) |

- Сообщение на срабатывание **одно**. Лестницы «пик растёт» и сообщения
  о взводе нет — решение владельца.
- Пол (возврат ниже порога) проверяется раньше отката: при обвале за одну
  проверку приходит «вернулся к порогу», а не «откат».
- Ограничения по времени («пик не обновлялся X часов») нет — обсуждали,
  не взяли.
- Логика фаз — чистая функция `step(state, gain)`, её и тестировать.

### Владелец

Только он видит `/swap`, `/bought` и получает уведомления. Задаётся
`SWAP_OWNER` — username без `@`, сравнение без учёта регистра. Bot API не
отдаёт ID по username, поэтому `chat_id` запоминается при первой `/swap`
или `/bought`; до этого `check_swap` ничего не делает. Чужим эти команды
не отвечают вовсе. Сменил владелец username — поправить `SWAP_OWNER`.

### `/bought` — разворот

`/bought <сумма> <ETH|WBTC|BTC>` — владелец обменял **всё**, что было
на руках, и получил `<сумма>`. Бот:

1. сравнивает сумму с прошлой `base` («против прошлых 0.3 WBTC: +3.33%»);
2. новая позиция: на руках `<сумма>` новой валюты, `base` — отданное количество
   старой; фаза `idle`;
3. пишет «Теперь слушаю X1 / X0» — дальше та же схема в обратную сторону;
4. дописывает обмен в `history`.

Купить ту же валюту, что на руках, нельзя — бот подскажет формат.

### Состояние

`SWAP_STATE_FILE` (на сервере `/var/lib/mbti-predict/swap_watch.json`):
`chat_id`, `asset`, `amount`, `base`, `phase`, `peak`, `history`
(`date`, `sold`, `sold_asset`, `bought`, `bought_asset`). Пока файла нет,
позиция берётся из `SWAP_ETH_AMOUNT` / `SWAP_WBTC_BASE` (ETH на руках);
после первой `/bought` окружение уже не влияет.

### Настройки (`/etc/mbti-predict.env`)

| Переменная | По умолчанию | Что |
|---|---|---|
| `SWAP_OWNER` | пусто — слежение выключено | username владельца |
| `SWAP_ETH_AMOUNT`, `SWAP_WBTC_BASE` | 0 | стартовая позиция |
| `SWAP_GAIN_PCT` | 2 | порог выгоды, % |
| `SWAP_TRAIL_PCT` | 1 | откат от пика, п.п. |
| `SWAP_FEE_PCT` | 0.875 | комиссия кошелька за обмен, % |
| `SWAP_CHECK_MINUTES` | 5 | проверка до порога; после — раз в минуту |

Поменял — перезапуск: `systemctl restart mbti-predict`.

## Деплой

Push в `main` → Actions → SSH-ключ с forced command → `deploy/deploy.sh`
на сервере: bare-репа `/var/repo/mbti-predict.git`, рабочее дерево
`/opt/mbti-predict`, `.venv` на Python 3.11 через `uv`, юнит из репы,
рестарт, проверка живости по `MainPID` через 10 с. Схема та же, что
у nutrition-bot; таблица путей — README, «Деплой».

- Системный Python на сервере — 3.8; бот живёт только в `.venv`. Новая
  зависимость — в `requirements.txt`, иначе её не будет.
- Перевыкатить без коммита: `gh workflow run deploy.yml` или на сервере
  `mbti-predict-deploy`.
- Логи: `journalctl -u mbti-predict -f`.
